Introduction

In class we learnt about four classifiers: LDA, QDA, naive Bayes, and k-nearest neighbors. Three of them are generative Gaussian methods that differ only in what they assume about the covariance; k-NN is the non-parametric alternative. This lab fits all four to the same medical diagnosis problem and compares them the way the slides told us to — with the confusion matrix, sensitivity, specificity, and the ROC curve.

Every code cell runs live in your browser via webR — no local R install needed. Edit any cell and re-run it. Packages and data load once when the page opens; give it a few seconds on first load. The k-NN cross-validation step is the heaviest cell and may take a little longer.

A note on caret

Following Lab 3, every model goes through caret::train() with one shared interface. We change the method argument and nothing else: "lda", "qda", "nb", "knn". The same cross-validation settings and the same centering/scaling apply to all four, so a difference in the results is a difference between the methods, not between how we called them.

The data: Wisconsin breast tumors

The Wisconsin Diagnostic Breast Cancer (WDBC) dataset records 569 tumors from fine-needle-aspirate images. Each tumor is labeled Benign or Malignant — a binary outcome, so the ROC curve and AUC work directly. Ten features are measured (radius, texture, smoothness, and so on); for each feature the data gives its mean, standard error, and “worst” value across the image, for 30 columns in all.

About 63% of the tumors are benign and 37% malignant — imbalanced, but not severely. Keep that split in mind: a classifier that called everything benign would already be 63% accurate while catching zero cancers (so accuracy alone will not be enough to track performance, we need to look at other metrics).

Choosing the features

The full 30 features separate the two classes almost perfectly (test AUC near 0.98 - take my word for it although you are free to check :)). Every method would look great and we would learn nothing about their differences; so we deliberately keep a harder subset: four features, each in its mean and standard-error form.

Train / test split

createDataPartition keeps the benign/malignant ratio the same in both parts. We tune and fit on the 427 training tumors and judge every model on the same 142 held-out test tumors.

LDA and QDA

LDA assumes a single shared covariance matrix across classes (linear boundary); QDA gives each class its own (quadratic boundary). Same call, one argument apart.

Naive Bayes

Naive Bayes keeps the generative recipe but assumes the features are independent within each class — a diagonal covariance. Here we use the Gaussian version (usekernel = FALSE), matching the density in the slides (but remember, Naive Bayes is the ONLY generative model that allows for mixed data types!)

The suppressWarnings() wrapper hides a harmless “numerical 0 probability” message: on a few outlying tumors the Gaussian density underflows to zero. It does not affect the fit. Note that technically Naive Bayes could have other distributions to support feature space as well!

k-Nearest Neighbors

k-NN is non-parametric — no distribution assumed. We let cross-validation pick k from the odd numbers 1 to 25. This is the heaviest cell; give it a moment.

Cross-validation chooses k = 15 — not k = 1. That matches the slide’s warning: a very small k overfits (low bias, high variance), so CV pulls us toward a smoother boundary.

Evaluating on the test set

The confusion matrix from the slides, in code. We set positive = "Malignant" because catching cancer is the outcome we care about, so sensitivity = “of the true malignant tumors, how many did we catch?” and specificity = “of the true benign tumors, how many did we correctly clear?”

Read the output against the slides: Accuracy is the overall proportion correct, Sensitivity and Specificity are the two class-wise rates, and Youden’s J = Sensitivity + Specificity − 1 summarizes both in one number.

Now the other three:

Putting the four side by side

Three things worth reading off this table:

  • QDA beats LDA (accuracy 0.838 vs 0.817, Youden’s J 0.650 vs 0.593). The two classes really do have different covariance structure, so letting each class keep its own — the quadratic boundary — pays off. This is the QDA lesson from the slides, made concrete.
  • Naive Bayes is the weakest here (accuracy 0.782). Its independence assumption is wrong: these tumor measurements are correlated, and throwing the correlations away costs accuracy. A reminder that “naive” is a real assumption, not a free lunch.
  • k-NN and QDA tie on accuracy, but they get there differently: k-NN has the highest specificity (0.910 — best at clearing benign tumors) while QDA has the highest sensitivity (0.774 — best at catching cancer). In a screening setting a missed malignancy is the costly error, which would push you toward QDA even at equal accuracy.

The ROC curve

Accuracy and the confusion matrix fix a single threshold (predict “Malignant” when its probability exceeds 0.5). The ROC curve sweeps every threshold, plotting sensitivity against 1 − specificity, and AUC is the area under it. Let’s draw all four on one plot.

A curve closer to the top-left corner is better. LDA and k-NN have the highest AUC (~0.90), even though QDA had the best single-threshold accuracy — a good illustration that “best classifier” depends on whether you care about one threshold or the whole range.

Try it yourself

The comparison above used set.seed(2155). Does the winner depend on that particular split? Change the seed, re-run the split and the four fits, and see whether the ranking holds.

Across most splits QDA stays ahead of LDA on this feature set — the covariance difference is a property of the data, not an accident of one split.

For a second experiment: the lab uses eight features. Add radius_mean and area_mean to the soft vector near the top, re-run everything, and watch every model’s accuracy jump — those two features carry most of the signal, which is exactly why we left them out to keep the comparison interesting.

Things worth remembering

  • One interface, four methods. train(method = ...) let us swap LDA, QDA, naive Bayes, and k-NN without relearning four APIs.
  • The covariance assumption is the dial. LDA (shared) → QDA (per-class) → naive Bayes (diagonal) are the same generative idea under different restrictions, and on this data QDA’s extra flexibility earned its keep while naive Bayes’ independence assumption cost it.
  • Accuracy is not the whole story. Sensitivity, specificity, Youden’s J, and AUC each answer a different question, and for a cancer screen the one that matters most is sensitivity.
