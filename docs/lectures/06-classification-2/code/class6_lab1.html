Introduction

In class we built support vector machines one idea at a time: a hyperplane that separates two classes, the maximal margin classifier that picks the widest such hyperplane, the soft margin that tolerates some violations, and kernels that bend the boundary. This lab has four parts:

  1. See the ideas. Simulated data with sliders — move a hyperplane by hand, push support vectors around, turn the cost dial, switch kernels.
  2. The tumor example from the slides. Real biopsy data, the same two features (cell size and cell shape uniformity), then all nine.
  3. More than two classes. Iris, three species, one-versus-one.
  4. Variable selection for classification. Thirty correlated tumor features: ordinary logistic regression breaks, and the lasso picks a handful.

Every code cell runs live in your browser via webR — no local R install needed. Packages and data load once when the page opens; give it a few seconds on first load.

Two kinds of cells. The interactive cells (the ones with sliders above them) run on their own and re-run every time you move a slider — just play. Every other cell runs when you click Run Code; run those in order from the top of each part, because later cells use objects made by earlier ones.

A warning about C before we start

The slides (and ISLR) write the soft margin with a budget \(C\):

\[\sum_{i=1}^n \epsilon_i \le C .\]

A large budget means more tolerance for points on the wrong side of the margin — a wider margin.

Every R package we use (kernlab, e1071, caret) instead uses a cost C: the price paid per unit of violation. A large cost means less tolerance — a narrower margin. The two run in opposite directions:

slides / ISLR budget \(C\) software cost C
wider margin, more violations, more support vectors large small
narrower margin, fewer violations, fewer support vectors small large

Everything in this lab uses the software meaning. When you read C = 100 below, think “violations are expensive”, not “a big budget”.

We use kernlab::ksvm() directly for the pictures in Part 1 and caret::train() for the real-data fits, following Lab 5: method = "svmLinear", "svmPoly", and "svmRadial" all call kernlab underneath.

Part 1 — Seeing the ideas

1.1 A hyperplane is just a sign

With \(p = 2\) features a hyperplane is a line, \(f(X) = \beta_0 + \beta_1 X_1 + \beta_2 X_2 = 0\). The slides normalize \(\beta_1^2 + \beta_2^2 = 1\); we build that in by writing \(\beta_1 = \cos\theta\), \(\beta_2 = \sin\theta\), so the two sliders below are the direction of the normal vector (the angle \(\theta\)) and the offset \(\beta_0\).

The shading shows the sign of \(f(X)\). A point with label \(y_i = \pm 1\) is on the correct side when \(y_i f(x_i) > 0\). When every point is on the correct side, you have a separating hyperplane, and — because \(\beta_1^2 + \beta_2^2 = 1\) — the smallest \(y_i f(x_i)\) is the margin \(M\): the distance from the line to the closest point.

Your job: find a separating hyperplane, then make \(M\) as large as you can. The title tells you the best achievable value.

viewof theta = Inputs.range([0, 355], {value: 0, step: 5, label: "angle θ (degrees)"})
viewof beta0 = Inputs.range([-5, 5], {value: -2, step: 0.05, label: "offset β₀"})

Notice how many different lines separate these two clouds — infinitely many. Separation alone does not pick a classifier; that is why we ask for the one with the largest margin. (Hint if you are stuck: the best angle is about 40° and the best offset about −2.75.)

1.2 The maximal margin classifier and its support vectors

ksvm() with a linear kernel and a huge cost (C = 10000, so no violations are affordable) finds the maximal margin hyperplane for us. The solid line is the hyperplane; the dashed lines are the margins; circled points are the support vectors.

The slides claim the support vectors are the only points that matter. Test it: pick a point and slide it away from (positive) or toward (negative) the boundary. The grey line is the original hyperplane for comparison.

viewof which_point = Inputs.radio(["a support vector", "a point far from the margin"], {value: "a support vector", label: "Move"})
viewof shift = Inputs.range([-0.4, 1.5], {value: 0, step: 0.05, label: "distance moved"})

What you should see:

  • Far-away point: slide it anywhere in its range — the hyperplane does not move at all. It is not a support vector, so it has no say.
  • Support vector, pulled toward the boundary (negative): the margin shrinks immediately. The whole classifier is at the mercy of this one point.
  • Support vector, pushed away (positive): the margin widens until another point takes over as a support vector.

That sensitivity is the maximal margin classifier’s weakness, and the reason the soft margin exists.

1.3 The soft margin: turning the cost dial

Now the classes overlap, so no separating hyperplane exists. The soft margin lets some points sit inside the margin, or even on the wrong side of the hyperplane. Slide the cost from cheap (left) to expensive (right).

viewof log10C = Inputs.range([-2, 2], {value: 0, step: 0.25, label: "log₁₀(cost C)"})

Sweep the slider end to end and watch three numbers move together:

cost C margin width support vectors training error
0.01 (cheap violations) 3.32 70 4%
1 0.91 16 4%
100 (expensive violations) 0.59 10 3%
  • Cheap violations → wide margin, many support vectors. 70 of the 100 points help set the boundary, so no single point can drag it around: low variance, higher bias.
  • Expensive violations → narrow margin, few support vectors. The fit bends to a handful of points near the boundary: low bias, higher variance.
  • Training error barely changes (4% → 3%). So training error cannot pick C for us — it will always favor expensive violations. We choose C the way we choose every tuning parameter: cross-validation. That is exactly what caret::train() does in Part 2.

1.4 Kernels: when a straight line won’t do

Here class +1 sits inside a ring and class -1 outside it — no straight line can separate them. We fit on 200 training points and report the error on 1,000 fresh test points from the same process. Try each kernel; for the radial kernel, also slide \(\gamma\) (kernlab calls it sigma).

viewof kern = Inputs.select(["linear", "polynomial, degree 2", "polynomial, degree 3", "radial"], {value: "linear", label: "kernel"})
viewof log10gamma = Inputs.range([-1, 2], {value: 0, step: 0.25, label: "log₁₀(γ)  (radial only)"})

Things to try:

kernel training error test error
linear 30.5% 28.5%
polynomial, degree 2 7.0% 7.4%
radial, γ = 1 8.5% 6.3%
radial, γ = 100 3.0% 21.0%
  • linear gives up and calls everything “outside” — one straight cut can’t carve out a disc, so it misclassifies the whole inside class.
  • polynomial, degree 2 gets close to the best possible: the true boundary \(X_1^2 + X_2^2 = 1.2^2\) is a degree-2 curve. (Nothing reaches 0% — the labels near the ring are noisy on purpose.)
  • radial, then slide \(\gamma\) all the way right. The training error keeps falling while the test error climbs as the boundary shrink-wraps individual points. Large \(\gamma\) = very local kernel = overfitting. \(\gamma\) is a flexibility dial, just like \(k\) in k-NN.

Why the degree-2 kernel works: the enlarged feature space

The slides’ trick was to add transformed features and fit a linear classifier in the bigger space. Plot the same points on \(X_1^2\) and \(X_2^2\) instead of \(X_1\) and \(X_2\):

In the transformed coordinates a straight line does the job. The polynomial kernel gets the same result without ever building those columns: it only needs inner products, which is what makes kernels cheap even when the enlarged space is huge (or, for the radial kernel, infinite-dimensional).

Part 2 — The tumor example from the slides

The slides motivated SVMs with benign vs. malignant tumors plotted on cell size uniformity and cell shape uniformity. Those come from the Wisconsin breast-cancer biopsy data, which ships with the MASS package as biopsy: 699 biopsies, nine cytology scores each rated 1–10, and the diagnosis.

683 complete biopsies, 65% benign. The scores are whole numbers from 1 to 10, so many patients share exactly the same (size, shape) pair — we jitter the points slightly so they don’t stack on top of each other:

Mostly separable, with a band of overlap in the middle — a job for the soft margin.

Split, then tune the cost by cross-validation

Cross-validation picks C = 8, but look at the y-axis: accuracy only runs from 0.934 to 0.951 across a 1,000-fold range of C. On this data the cost barely matters. That is common — and it’s why we tune on a log-spaced grid rather than agonizing over one value.

The fitted boundary

predict() on a grid of (size, shape) values paints the regions the SVM assigns to each class. caret applies the same centering and scaling to the grid that it applied to the training data.

How well does it do on the test set?

As in Lab 5 we set positive = "Malignant", so sensitivity is the share of cancers we catch.

With just two features the linear SVM gets 95.3% of the 170 test biopsies right, catching 56 of 59 cancers (sensitivity 0.949) while clearing 106 of 111 benign tumors (specificity 0.955).

All nine features, three kernels

Now use every score, and compare the three kernels from class. All three go through the same train() call; only method changes. This is the heaviest cell in Part 2 (the polynomial grid fits 270 models) — give it a moment.

  • More features help: going from two scores to nine lifts accuracy from 0.953 to 0.971 and sensitivity from 0.949 to 0.983 (one missed cancer instead of three).
  • More flexible kernels don’t: linear, polynomial, and radial land within one test biopsy of each other. Cross-validation even picked the smallest cost on the grid for the linear kernel — the widest, most forgiving margin.
  • The lesson from §1.4 in reverse: a kernel only pays off when the true boundary is curved. These cytology scores rise together as a tumor turns malignant, so a straight cut is already about as good as it gets. Try the linear kernel first; reach for a kernel only when CV says it helps.

Part 3 — More than two classes

SVMs are binary by construction. The slides gave two ways round that: one-versus-all (fit \(K\) classifiers, each class against the rest) and one-versus-one (fit all \(\binom{K}{2}\) pairwise classifiers and let them vote). kernlab uses one-versus-one. With three iris species that means \(\binom{3}{2} = 3\) binary SVMs inside one fitted model — we can count them:

The interactive plot below shows the combined vote as three-colored decision regions. The two feature pairs give very different problems:

viewof iris_features = Inputs.radio(["petal", "sepal"], {value: "petal", label: "features"})
viewof iris_kernel = Inputs.radio(["linear", "radial"], {value: "linear", label: "kernel"})
  • Petal features: both kernels separate the three species almost perfectly (10-fold CV error 4.7% linear, 4.0% radial). Setosa sits far off on its own; the two classifiers that involve it are easy.
  • Sepal features: the error jumps to about 21% (linear) and 25% (radial). Versicolor and virginica overlap heavily on sepal measurements, and no kernel can separate points that sit on top of each other — the radial kernel just draws a more contorted boundary through the overlap and does worse. Better features beat a fancier kernel.

Part 4 — Variable selection for classification

Everything so far used a few hand-picked features. Real problems often come with many correlated candidates, and we would like the data to tell us which ones matter. Back to the Wisconsin Diagnostic (WDBC) data from Lab 5, this time with all 30 features: ten nuclear measurements, each recorded as a mean, a standard error, and a “worst” value.

Why not just throw everything into logistic regression?

R warns that the algorithm did not converge and that fitted probabilities are numerically 0 or 1. The training tumors are perfectly separable in 30 dimensions, so the likelihood keeps improving as the coefficients grow — the median coefficient is about 500 and the largest about 44,000, on the log-odds scale. These estimates mean nothing, and (spoiler) the model does worst of everything we’ll try on the test set.

The lasso: logistic regression with a penalty

The fix is the same one we used for regression in Lab 3: add a penalty. The lasso maximizes

\[\underbrace{\sum_{i=1}^n \log L(\beta;\, y_i, x_i)}_{\text{logistic log-likelihood}} \; - \; \lambda \sum_{j=1}^{p} |\beta_j| .\]

The absolute-value penalty does two jobs at once: it keeps the coefficients finite, and it sets many of them exactly to zero — so fitting the model is selecting variables. \(\lambda\) controls how many survive. glmnet fits the whole path of \(\lambda\) values in one call (alpha = 1 is the lasso; alpha = 0 would be ridge).

The features are on very different scales (areas in the hundreds, smoothness around 0.1), and the penalty treats every \(\beta_j\) alike, so we standardize first, using the training means and SDs for both sets.

Read the plot right to left: at large \(\lambda\) (right) every coefficient is zero; as \(\lambda\) shrinks, features enter one at a time. The numbers along the top count how many are in the model.

Pick your own λ

Slide \(\lambda\) and watch which features survive and how the test accuracy responds.

viewof log10lambda = Inputs.range([-3.5, -0.5], {value: -1, step: 0.1, label: "log₁₀(λ)"})

A few settings to try:

log₁₀(λ) features kept test accuracy
−3.5 21 97.9%
−2.0 8 97.9%
−1.0 4 95.1%
−0.5 2 69.7%

From 21 features down to 8 the test accuracy does not move: those extra 13 features were redundant. Around 6 features it starts to slip, and at 2 the model has thrown away real signal. Somewhere in between is the smallest model that is still as good as the big one — which is what cross-validation will find.

Letting cross-validation choose λ

cv.glmnet() runs 10-fold CV along the whole path. It reports two choices: lambda.min (the lowest CV error) and lambda.1se (the largest \(\lambda\) within one standard error of that minimum — the simplest model that is statistically as good). For selection we usually prefer lambda.1se.

The lambda.1se model keeps 10 of the 30 features. Notice what’s there: mostly “worst” measurements (the most abnormal cells in the image) and the concavity / concave points family — the irregular, indented cell outlines a pathologist looks for. Of radius, perimeter, and area — three near-copies of “how big is the nucleus” — the lasso keeps area_worst and radius_worst but not perimeter: with correlated features, the lasso tends to keep one or two representatives and drop the rest.

Does selecting features cost us anything?

Compare, on the same 142 test tumors: the unpenalized logistic model, the lasso, ridge (penalized but no selection), and a linear SVM trained on all 30 features vs. only the lasso’s picks.

  • The unpenalized model is worst (0.944) — the inflated coefficients from above do real damage on new data.
  • Lasso with 10 features = ridge with 30 = SVM with 30 (all 0.979). We got a model a third the size at no cost in accuracy, and one that names which measurements matter.
  • The SVM on the lasso’s 10 features is one tumor behind (0.972). Variable selection by one method can be handed to another.
  • Everything — the standardization, the λ choice, the selected list — came from the training tumors only. Selecting features on all the data and then “testing” on part of it leaks information and makes the test accuracy look better than it is.

How stable is the selection?

The lasso’s choice depends on the data it saw — including the random assignment of CV folds. Re-run the CV with 10 different fold assignments and count how often each feature is picked. To keep it quick we search a 30-point λ grid around where lambda.1se landed. This is the slowest cell in the lab — allow up to a minute.

Seven features are chosen in every run — concavity_mean, concave_points_mean, radius_worst, texture_worst, smoothness_worst, concave_points_worst, symmetry_worst. Those you can trust. The rest come and go with nothing more than a reshuffle of the CV folds (area_worst, picked in our single run above, rarely or never makes the cut here). A single lasso fit gives one list; a stability check tells you which parts of it are real. Report the stable core, not whatever one run happened to say.

A connection worth knowing

The SVM is secretly a penalized method too. ISLR §9.5 shows the support vector classifier solves

\[\min_{\beta}\; \sum_{i=1}^n \max\big[0,\, 1 - y_i f(x_i)\big] \;+\; \lambda \sum_{j=1}^p \beta_j^2 ,\]

a hinge loss plus a ridge penalty — and \(\lambda\) plays the role of \(1/C\) for the software cost. Swap the hinge loss for the logistic loss and you have ridge logistic regression; swap the ridge penalty for the lasso penalty and you have the lasso. “Regularization for classification” is one recipe — loss + penalty — with interchangeable parts.

Things worth remembering

  • The margin is decided by a few points. Only the support vectors shape the SVM; everything else could move (within limits) without changing the fit.
  • Cost C in software is the opposite of the budget \(C\) on the slides. Large software C = expensive violations = narrow margin = low bias, high variance. Tune it by cross-validation, never by training error.
  • Kernels buy flexibility, and flexibility has to be earned. On the ring a degree-2 kernel is exactly right; on the tumor data a straight line is already as good as anything fancier.
  • Multi-class SVMs are a vote. kernlab fits one binary SVM per pair of classes.
  • With many correlated features, penalize. Unpenalized logistic regression broke on 30 correlated features; the lasso kept the coefficients sane and selected a short list — but check how stable that list is before you interpret it.
